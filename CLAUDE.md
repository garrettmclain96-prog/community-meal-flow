# Working in ProvisionLoop

Read and follow [AGENTS.md](./AGENTS.md); do not duplicate or rewrite it.

Before work, read:

- [Design](./design.md): architecture, risks and decisions.
- [Requirements](./requirements.md): numbered EARS criteria and open guarantees.
- [Tasks](./tasks.md): ordered execution and completion evidence.
- [Operating contract](./docs/ai/how-claude-works-with-garrett.md): full context,
  verification, escalation and memory protocol.

Garrett is iPhone-only. Execute available work; make manual output complete and
copy-paste-ready. Supply full files for manual replacement, not insertion fragments.
State material assumptions before long work. Never fabricate contacts, partners,
account identities, numbers or test outcomes. Preserve scope exclusions.

Use repository facts over stale memory. Continue authorized reversible work
without repeated confirmation. Escalate missing identity/access only after
completing unblocked work. Never request secrets in chat or bypass denied access.

Prove changes with named formatting, typecheck, lint, build and smoke checks.
Distinguish source checks, mocks, browser checks and deployed verification.
Report unavailable checks as blocked; never label unobserved amounts as zero.
Payments remain sandbox-only. Do not send external messages without authorization.

Update design version/date/changelog, requirements and tasks as evidence changes.
Record new decisions in docs/adr and link them from design.md. Keep credentials
and household data out of docs. End with the result, checks, blockers and exact
next action. VaultOS and GloveGate are out of scope this pass.
